# Визуализатор графа зависимостей пакетов

Практическая работа №2 по дисциплине «Конфигурационное управление»,
вариант 24.

Консольное приложение (CLI) для построения графа зависимостей пакетов
Ubuntu (apt). Менеджеры пакетов и сторонние библиотеки для получения
зависимостей не используются: индекс пакетов скачивается и разбирается
самостоятельно.

## Этапы

**Этап 1. Минимальный прототип с конфигурацией**:

- все параметры задаются опциями командной строки;
- проверка каждого параметра с выводом понятных сообщений об ошибках;
- вывод всех параметров в формате `ключ=значение` (только на этапе 1).

**Этап 2. Сбор данных**:

- загрузка индекса пакетов Ubuntu (`Packages.gz`) по URL репозитория;
- поиск пакета заданной пользователем версии;
- извлечение прямых зависимостей (`Pre-Depends` и `Depends`);
- обработка ошибок: пакет или версия не найдены, репозиторий недоступен,
  неверный формат индекса.

**Этап 3. Основные операции**:

- построение графа зависимостей с учётом транзитивности алгоритмом
  DFS с рекурсией;
- ограничение глубины анализа параметром `--max-depth`;
- обнаружение и вывод циклических зависимостей;
- разрешение виртуальных пакетов (`Provides`) и альтернатив (`|`);
- тестовый режим: граф репозитория из файла, пакеты — заглавные
  латинские буквы.

**Этап 4. Дополнительные операции**:

- режим вывода обратных зависимостей (`--reverse`): пакеты, которые
  зависят от заданного пакета, в том числе транзитивно;
- используется тот же алгоритм обхода (DFS), что и на этапе 3,
  но по обращённому графу.

## Параметры командной строки

| Параметр | Обязательный | По умолчанию | Описание |
|---|---|---|---|
| `--package NAME` | да | — | Имя анализируемого пакета |
| `--repo URL\|PATH` | да | — | URL репозитория или путь к файлу тестового репозитория |
| `--test-mode` | нет | выключен | Режим работы с тестовым репозиторием |
| `--version VER` | да* | — | Версия пакета (*в тестовом режиме необязательна) |
| `--output FILE` | нет | `graph.svg` | Имя файла с изображением графа |
| `--max-depth N` | нет | `3` | Максимальная глубина анализа зависимостей |
| `--reverse` | нет | выключен | Вывести обратные зависимости (кто зависит от пакета) |
| `-h`, `--help` | нет | — | Справка |

### Правила проверки

| Параметр | Ошибкой считается |
|---|---|
| `--package` | Обычный режим: имя не соответствует правилам Debian (строчные латинские буквы, цифры, `+ - .`, начинается с буквы или цифры, минимум 2 символа). Тестовый режим: имя не из заглавных латинских букв |
| `--repo` | Обычный режим: строка не начинается с `http://` или `https://`. Тестовый режим: файл не существует |
| `--version` | Пустая (вне тестового режима) или содержит недопустимые символы (допустимы буквы, цифры, `. + ~ : -`) |
| `--output` | Расширение не `.svg` или папка для файла не существует |
| `--max-depth` | Не целое число или меньше 1 |

Если ошибок несколько, выводятся все сразу. Сообщения выводятся
в `stderr`, программа завершается с кодом `1` (ошибки разбора
`argparse` — с кодом `2`).

## Получение данных

### Репозиторий Ubuntu

По URL репозитория формируется адрес индекса пакетов:

```
<repo>/dists/noble/main/binary-amd64/Packages.gz
```

Дистрибутив (`noble`, Ubuntu 24.04), компонент (`main`) и архитектура
(`amd64`) заданы константами в `apt_repo.py`.

Индекс — это текст, сжатый gzip. Он состоит из записей, разделённых
пустой строкой. Каждая запись — набор полей `Ключ: значение`;
строки, начинающиеся с пробела, продолжают предыдущее поле:

```
Package: curl
Version: 8.5.0-2ubuntu10
Depends: libc6 (>= 2.34), libcurl4t64 (= 8.5.0-2ubuntu10), zlib1g (>= 1:1.1.4)
```

Зависимости берутся из полей `Pre-Depends` и `Depends`. Формат:

- зависимости разделены запятыми;
- альтернативы внутри одной зависимости разделены `|`
  (`sssd | winbind` — нужен любой из пакетов);
- в скобках — ограничение версии (`>=`, `<=`, `=`, `<<`, `>>`);
- суффикс архитектуры (`perl:any`) отбрасывается.

При построении графа:

- из альтернатив `a | b` выбирается первая, которая есть в репозитории;
- виртуальный пакет (например, `awk`) заменяется первым пакетом,
  который его предоставляет через поле `Provides` (`gawk`);
- для корневого пакета берётся версия, заданная пользователем,
  для остальных — версия из репозитория.

### Тестовый репозиторий

Текстовый файл, каждая строка — пакет и список его прямых зависимостей.
Пустые строки и строки, начинающиеся с `#`, пропускаются:

```
# комментарий
A: B C
B: C
C:
```

Зависимость, не описанная в файле, считается отсутствующей в репозитории.

## Построение графа

Граф строится рекурсивным обходом в глубину (DFS) из анализируемого
пакета (класс `DependencyGraph` в `graph.py`):

1. Корневой пакет имеет глубину 0, его прямые зависимости — 1 и т.д.
2. Зависимости пакета запрашиваются, только если его глубина меньше
   `--max-depth`. Пакеты на максимальной глубине попадают в граф,
   но их зависимости не анализируются.
3. Каждый пакет обходится один раз. Если пакет позже найден по более
   короткому пути, он обходится повторно с меньшей глубиной, чтобы
   ограничение глубины не отрезало его зависимости.
4. Пакеты текущего пути хранятся в стеке. Если зависимость уже есть
   в стеке, найден цикл: он запоминается, и обход по этой связи
   прекращается. Поэтому циклы не приводят к бесконечной рекурсии.
5. Пакет, которого нет в репозитории, помечается как отсутствующий.

## Обратные зависимости

Обратные зависимости пакета `X` — пакеты, которые зависят от `X`
(напрямую или транзитивно).

1. Строится полный граф прямых зависимостей всего репозитория:
   `пакет -> его зависимости` (для Ubuntu — по всем пакетам индекса,
   с тем же разрешением альтернатив и виртуальных пакетов).
2. Граф обращается функцией `reverse_graph`: каждая связь `A -> B`
   превращается в `B -> A`.
3. По обращённому графу выполняется тот же обход `DependencyGraph`
   с ограничением глубины и обнаружением циклов.

В выводе стрелка `<-` означает «от пакета слева зависят пакеты справа».
Циклы выводятся в направлении прямых зависимостей.

Ограничения версий (`>= 2.34`) при поиске обратных зависимостей
не учитываются: в `noble main` у каждого пакета одна версия.

## Модули и функции

### `main.py`

| Функция | Описание |
|---|---|
| `parse_args(argv)` | Разбирает параметры командной строки (`argparse`) |
| `validate_package/repo/version/output/depth(...)` | Проверяют отдельные параметры, возвращают текст ошибки или `None` |
| `validate(args)` | Запускает все проверки, возвращает список ошибок |
| `dependency_source(args)` | Создаёт функцию получения зависимостей (прямых или обратных): из репозитория Ubuntu или тестового файла |
| `print_graph(args, graph)` | Выводит граф (`->` для прямых, `<-` для обратных зависимостей), число пакетов и связей, найденные циклы |
| `fail(messages)` | Выводит ошибки в `stderr` и завершает программу с кодом 1 |
| `main(argv)` | Точка входа |

### `apt_repo.py`

| Функция | Описание |
|---|---|
| `packages_url(repo)` | Формирует URL файла `Packages.gz` |
| `download_index(url)` | Скачивает и распаковывает индекс пакетов в памяти |
| `parse_stanza(block)` | Разбирает одну запись в словарь полей |
| `parse_packages(text)` | Разбирает весь индекс в список записей |
| `find_package(stanzas, name, version)` | Ищет запись пакета заданной версии |
| `parse_dependency(item)` | Разбирает одну зависимость в `(имя, оператор, версия)` |
| `parse_depends(value)` | Разбирает поле зависимостей в список групп альтернатив |
| `stanza_dependencies(stanza)` | Собирает зависимости из `Pre-Depends` и `Depends` |
| `AptIndex(stanzas)` | Индекс пакетов: словарь пакетов и словарь виртуальных пакетов (`Provides`) |
| `AptIndex.resolve(name)` | Возвращает реальный пакет для имени (в т.ч. виртуального) или `None` |
| `AptIndex.choose(group)` | Выбирает пакет из группы альтернатив |
| `AptIndex.dependency_names(stanza)` | Список имён прямых зависимостей без повторов |
| `load_index(repo)` | Скачивает и разбирает индекс, возвращает `AptIndex` |
| `dependency_source(repo, root, version)` | Загружает индекс, проверяет корневой пакет и возвращает функцию получения зависимостей |
| `reverse_dependency_source(repo, root, version)` | То же для обратных зависимостей: строит граф всего репозитория и обращает его |
| `RepoError` | Исключение для всех ошибок получения данных |

### `graph_file.py`

| Функция | Описание |
|---|---|
| `parse_graph_line(line, num)` | Разбирает строку `ПАКЕТ: ЗАВИСИМОСТИ` |
| `load_graph(path)` | Загружает тестовый репозиторий в словарь |
| `dependency_source(path, root)` | Проверяет корневой пакет и возвращает функцию получения зависимостей |
| `reverse_dependency_source(path, root)` | То же для обратных зависимостей |

### `graph.py`

| Элемент | Описание |
|---|---|
| `DependencyGraph(get_deps, max_depth)` | Граф зависимостей. `get_deps(name)` возвращает список зависимостей или `None`, если пакета нет |
| `build(root)` | Строит граф из корневого пакета |
| `visit(name, depth)` | Рекурсивный шаг DFS |
| `nodes()` | Пакеты, отсортированные по глубине |
| `edge_count()` | Число связей |
| `edges` | Словарь `пакет -> список зависимостей` |
| `depths` | Словарь `пакет -> глубина` |
| `missing` | Пакеты, отсутствующие в репозитории |
| `cycles` | Найденные циклы |
| `reverse_graph(graph)` | Обращает граф: `A -> B` превращается в `B -> A` |

### Обработка ошибок получения данных

| Ситуация | Сообщение |
|---|---|
| Пакет не найден | `пакет '<имя>' не найден в репозитории` |
| Версия не найдена | `версия '<v>' пакета '<имя>' не найдена, доступные версии: ...` |
| Репозиторий не найден | `<url>: сервер вернул HTTP 404` |
| Сервер недоступен | `<url>: не удалось подключиться: ...` |
| Файл — не gzip | `<url>: неверный формат индекса пакетов` |
| Ошибка в тестовом файле | `строка N: ожидается формат 'ПАКЕТ: ЗАВИСИМОСТИ'` |

## Запуск

Требуется Python 3.8+ и доступ в интернет (для реального репозитория).

```sh
./run.sh --package NAME --repo URL [--version VER] [--test-mode] \
         [--output FILE] [--max-depth N]
```
